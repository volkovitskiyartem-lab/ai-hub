# AI Hub — локальный MCP-мост

AI Hub предоставляет Codex инструменты `submit_task`, `project_stats`, `record_review`. GigaChat получает только текст задания; доступ к файлам, терминалу и инструментам ему не предоставляется. Ответ внешней модели недоверенный: Codex проверяет его и тестирует в разрешённой среде. Код модели не выполняется мостом.

## Состояние

Подключение реального GigaChat **не проверено**: локальные тесты используют имитатор, ключ не настроен, API не вызывался. Существующие проекты и глобальная конфигурация Codex не изменялись. Для реального вызова нужны проверенные сертификат, ключ, тариф и отдельное разрешение пользователя на потенциально платное обращение.

Требуется Node.js 24 (встроенный `node:sqlite`). Зависимости устанавливать не нужно.

## Локальные тесты

Откройте приложение «Терминал», вставьте команду целиком и нажмите Enter:

```sh
cd "$HOME/ai-hub" && node --test test/*.test.mjs
```

Сервер можно проверить без подключений так:

```sh
cd "$HOME/ai-hub" && printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"manual","version":"1"}}}' '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | node src/server.mjs
```

На stdout сервер выводит только сообщения MCP, диагностика идёт в stderr. По умолчанию создаётся папка `state` внутри AI Hub; `AI_HUB_HOME` позволяет задать другую папку состояния. Файл `state/config.json` при отсутствии считается пустым: все проекты заблокированы. Образец `config.example.json` выключен и не содержит разрешённых подключений.

## Настройка после отдельного разрешения

1. Проверьте действующие условия вашего аккаунта, тип `scope` и доступную модель у GigaChat. Разрешение на разработку само по себе не является разрешением на платный запрос.
2. Через приложение «Связка ключей» macOS создайте элемент типа «пароль» в своей связке: имя/служба `codex-ai-hub-gigachat`, учётная запись `gigachat-api`, пароль — ваш Authorization Key. Не присылайте ключ в чат. macOS может запросить доступ к элементу при работе моста.
3. Получите корневой сертификат в соответствии с [официальной документацией](https://developers.sber.ru/docs/ru/gigachat/certificates), отдельно проверьте его подлинность по официальному каналу и укажите абсолютный путь к PEM в `ca_file`. Папка состояния не добавляет сертификат в глобальное хранилище. Проверка TLS всегда включена.
4. Создайте `state/config.json` на основе `config.example.json`, включите только конкретную модель и тестовый проект, задайте лимиты и проверенную цену **за миллион входных и выходных токенов в одной валюте**, соответствующую вашему договору. `null` блокирует запросы. Не интерпретируйте цену пакета как точную цену дополнительного запроса без проверки условий. `max_cost` и накопленный резерв выражаются в той же валюте. Установите `max_requests` и `max_output_tokens`.
5. Получите отдельное согласие на вызов API. Затем потребуется отдельное согласие на изменение глобальной конфигурации Codex. До изменения сохраните резервную копию `~/.codex/config.toml`; регистрация выполняется через `codex mcp add`, а откат — удалением только добавленного сервера и при необходимости восстановлением копии. Точные команды следует подготовить при согласовании с учётом состояния конфигурации на тот момент.

## Проекты и модели

Ключ в `projects` — идентификатор разрешения, а не путь к папке. Сервер сам не читает проект. Для нового проекта добавьте объект с `enabled`, `models`, `categories`, `max_requests`, `max_cost`, `price_per_million` и `max_output_tokens`. По умолчанию доступ отсутствует. Проекты с финансовой или внутренней информацией Мосгортур требуют отдельного разрешения. Никогда не отправляйте пароли, ключи, персональные данные, финансовые операции, конфиденциальную информацию или целый репозиторий без отдельного разрешения. Фильтр типичных секретов носит вспомогательный характер и не распознаёт все персональные или конфиденциальные данные; проверка содержимого обязательна до вызова инструмента.

Для новой модели реализуйте адаптер с методом `async run({prompt, maxOutputTokens})`, возвращающим `{text, usage: {input, output}}`; затем явно зарегистрируйте его в `src/server.mjs` и настройте разрешения. Ошибки адаптера не должны содержать секреты в пользовательских результатах или журнале. Локальные языковые модели не предусмотрены.

## Лимиты и журнал

SQLite хранит метаданные: проект, модель, ID, номер доработки, статус, токены при наличии, оценку стоимости, резерв, время и итог тестирования. Содержание запросов, ответов, ключей и ошибок поставщика не записывается. Лимиты запросов и бюджета накапливаются за всё время существования базы; автоматического сброса по месяцам нет. Неизвестный расход обозначается отсутствующими данными, а резерв остаётся занятым, включая запросы с ошибкой. Оценка предполагает заданные пользователем цены и может отличаться от счёта поставщика: кэширование, пакеты, НДС и токенизация могут учитываться иначе. Символьная оценка входа и резерв не являются гарантией верхней границы фактического счёта; используйте также лимиты поставщика. Повторных запросов к API нет, чтобы не повторить потенциально тарифицируемую операцию. Максимум две последовательные доработки на задачу.

`record_review` фиксирует оценку Codex и статус тестов, но не запускает тесты. Политика решений о целесообразности делегирования и проверке результата исполняется Codex; сервер сам не может проверить, что Codex достаточно тщательно проверил код. Внешние вызовы запрещены при выключенном проекте/модели, отсутствующей категории, цене или при превышении локальных лимитов.

## Восстановление

На данном этапе глобальные настройки не менялись. Чтобы остановить сервер, завершите его процесс; для удаления локального состояния после проверки, что оно больше не нужно, удалите папку `state` вручную в Finder. Элемент Keychain, если вы его создадите, удаляется отдельно в приложении «Связка ключей». Глобальную конфигурацию восстанавливайте только из сделанной перед её изменением резервной копии с учётом последующих изменений.
